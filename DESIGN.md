# Design notes

Why the sorter is built the way it is. [README.md](README.md) covers using it.

- **No build, no dependencies.** `sorter.js` is a UMD-style classic script (`window.MtgSort` in a page, `module.exports` in Node), so `index.html` works opened straight from disk, where module scripts are blocked. The shared look is vendored rather than linked for the same reason (see below). `cli.js` and the tests are CommonJS on Node's built-in test runner.
- **Scryfall's API by default, the bulk file by choice.** Most people sort a few hundred to a few thousand cards, and asking them to download a few-hundred-MB file first is too much, so the default is the API and the bulk file is opt-in. `POST /cards/collection` takes 75 identifiers per request, and Scryfall limits that endpoint to about 2 requests a second (tighter than the ~10 its other endpoints allow), so request starts are 500 ms apart. An early version went 100 ms apart and retried a 429 after 1, 2 and 4 seconds; real collections got rate-limited and every retry landed inside the lockout. A 429 now waits for `Retry-After` when it's readable (Node only) or 30, 60, 120, 240 seconds (30 s is Scryfall's documented lockout; observed `Retry-After` runs 30–60 s), doubles the spacing for the rest of the run (up to 4 s), and gives up after four waits. <a id="hidden-429"></a>In a browser the 429 never arrives as a 429: Scryfall sends it without `Access-Control-Allow-Origin`, so `fetch` rejects with a bare `TypeError` ("Failed to fetch") that looks exactly like a dropped connection. A 3,490-row ManaBox export hit this around request 20–40 of 46 even at 500 ms spacing. So a request that fails outright is treated as a probable 429 and gets the same waits, unless `navigator.onLine` is false, which fails at once. In Node a real outage now also waits through the four retries before failing; that's the price of one code path. The CLI sends a `User-Agent`, as Scryfall asks; browsers can't set one.
- **Lookups fall back.** Each row tries Scryfall ID, then set + collector number, then name + set, then name, moving on only when Scryfall misses. Found cards are matched back to what was asked by key (`keysFor`), not by position, because `/cards/collection` leaves misses out of `data`.
- **Grouping follows the frame** by default, not the rules' color or color identity: the front face for transform, modal DFC, adventure, flip, and reversible cards; both halves for `split` and `aftermath`. When a front face has no `colors` (adventure and flip faces don't), its mana cost decides. Land is checked first, on the front face's type line. Tokens, emblems, and art cards get their own group. `identity` swaps in `color_identity`.
- **Within a color, cards file by type, the way sellers sort a box**: Planeswalker, Creature, Instant, Enchantment, Sorcery, then artifacts (Equipment, then Vehicles and Spacecraft together, then the rest), then anything else, such as Battles. It reads the front face's type line the way the tracker this came from does on Scryfall's real data: card types before " — ", subtypes after, faces split on " // ". A card with two types takes the first one in that order, so artifact and enchantment creatures file with creatures and a Kindred enchantment with enchantments. Lands keep their own color group and one shared rank. `types: false` skips it.
- **The output is the input reordered.** Every column and value is kept; it only fills blank Scryfall IDs and adds `Color Group` and `Card Type` (each overwritten in place on a re-run). Separator, line endings, and BOM are kept. Blank rows are dropped.
- **Tested against fakes, so check new layouts against the real API.** `test/cards.json` mirrors Scryfall's shapes per layout (top-level `colors` missing on transform, MDFC, and reversible cards; faces without `colors` on adventure and flip cards), and `test/fake-scryfall.js` answers like `/cards/collection`. When Scryfall adds a layout, check a real card of it before trusting the fixture. The fake once matched a full "Front // Back" name, which real `/cards/collection` never does (it matches either face's name alone), so every name lookup of a two-faced card missed in real use while the tests passed: 122 of 122 such rows in a real ManaBox export. Rows now send the front face's name, and the fake answers only to face names.
- **Progress is staged, and only stage changes are announced.** `onProgress` reports read, lookup, retry passes, and sort, with cards found and an estimate from the measured time per request (never faster than the pace). The page puts the stage in a `role="status"` line and the counters in a plain line beside a `<progress>`, so screen readers hear "Looking up 7,500 cards" once, not every tick. A 429 shows a countdown. **Stop** aborts through an `AbortSignal` that reaches `fetch`, the pacing sleeps, and the bulk reader.
- **Bulk files are streamed, never held whole, in either of Scryfall's formats.** Scryfall serves bulk files as JSON Lines (one card per line) and still offers the older single JSON array; `arraySplitter` (a brace- and string-aware scanner that carries a partial object across chunks, tested at every two-cut boundary in both formats) tells them apart by the first character that isn't whitespace or a byte-order mark, `[` for an array, and emits each top-level card either way. The first version read only arrays, so a real download failed with "no cards in it": inside a line-per-card file it emitted each card's nested `prices`, `legalities` and faces instead. Its full-size test file was an array built from the same assumption, which is why nothing caught it; test fixtures for a format should come from the real thing. and keeps a ~300-byte slim copy of each card, indexed by the same keys as the API lookups. `resolve` checks it before the API, and `offline` skips the API. A 327 MB, 110,000-card file sorted a 9,000-row export in 3.8 s (~400 MB of memory) from the CLI and 4.2 s in Chromium, with no requests; a re-sort in the page reuses the parsed file. Reading from disk never waits on anything, so `readBulk` gives the event loop a turn every 50 ms, or the page wouldn't repaint or take Stop until the end. Default Cards lacks non-English printings' IDs; those rows find their English printing by set and collector number, which has the same colors.
- **The look is furioursus.dev's.** Paper-toned page, ink rules opening each section, small uppercase labels, square fields, an ink-filled main button and ghost secondary buttons that lift onto a 2px pink offset on hover and press into it, pink and green as the only accents. The colors, fonts and light/dark switch come from [`@furioursus/ui`](https://github.com/furioursus/furioursus-ui), the package furioursus.dev uses too, vendored as unmodified copies in `vendor/furioursus-ui/` so the page needs no network or build; that folder's README says how to update them. Don't define colors in `index.html`: change the package instead, so the two sites can't drift. `test/page.test.js` fails if the page uses a variable the vendored tokens don't define. Light and dark follow the system until the toggle is used; the choice is saved only while it differs from the system's mode.
- **Every control shows its state by shape as well as color**: a 2px pink focus ring, an underline on hover for links and the summary, the pink offset on boxed buttons, an ink border on fields, a 2px bar on hovered table rows, diagonal stripes on Sort while it works (`aria-busy`), 45% opacity when disabled. Transitions are 120 ms and stop under reduced motion.
- **Fonts: Bricolage Grotesque for display, the system's monospace for text.** Bricolage (SIL Open Font License, `fonts/OFL.txt`) is a Latin subset inlined as a data URI, so the page still works opened from disk. The site this look comes from sets body text in MonoLisa, which is a commercial font licensed for that site; it can't be redistributed in a public repo, so don't add it here. The shared `--font-mono` names MonoLisa first, so a visitor who happens to have it installed sees it; everyone else gets the system monospace. `ui-monospace` gives SF Mono on Apple systems and Cascadia or Consolas on Windows.
- **`[hidden]` is forced to `display: none`.** Several elements get `display: grid` from a class, which would otherwise override the `hidden` attribute and leave the progress panel showing.
- **`<details>` is spaced with margins, not a grid gap**: its children sit in a `::details-content` box, so a gap set on `<details>` doesn't reach them.
