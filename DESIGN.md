# Design notes

Why the sorter is built the way it is. [README.md](README.md) covers using it.

- **No build, no dependencies.** `sorter.js` is a UMD-style classic script (`window.MtgSort` in a page, `module.exports` in Node), so `index.html` works opened straight from disk, where module scripts are blocked. `cli.js` and the tests are CommonJS on Node's built-in test runner.
- **Scryfall's API by default, the bulk file by choice.** Most people sort a few hundred to a few thousand cards, and asking them to download a few-hundred-MB file first is too much, so the default is the API and the bulk file is opt-in. `POST /cards/collection` takes 75 identifiers per request, and Scryfall limits that endpoint to about 2 requests a second (tighter than the ~10 its other endpoints allow), so request starts are 500 ms apart. An early version went 100 ms apart and retried a 429 after 1, 2 and 4 seconds; real collections got rate-limited and every retry landed inside the lockout. A 429 now waits for `Retry-After` when it's readable (Node only: browsers can't read it cross-origin) or 10, 20, 40, 80 seconds, doubles the spacing for the rest of the run (up to 4 s), and gives up after four waits. The CLI sends a `User-Agent`, as Scryfall asks; browsers can't set one.
- **Lookups fall back.** Each row tries Scryfall ID, then set + collector number, then name + set, then name, moving on only when Scryfall misses. Found cards are matched back to what was asked by key (`keysFor`), not by position, because `/cards/collection` leaves misses out of `data`.
- **Grouping follows the frame** by default, not the rules' color or color identity: the front face for transform, modal DFC, adventure, flip, and reversible cards; both halves for `split` and `aftermath`. When a front face has no `colors` (adventure and flip faces don't), its mana cost decides. Land is checked first, on the front face's type line. Tokens, emblems, and art cards get their own group. `identity` swaps in `color_identity`.
- **The output is the input reordered.** Every column and value is kept; it only fills blank Scryfall IDs and adds `Color Group` (overwritten in place on a re-run). Separator, line endings, and BOM are kept. Blank rows are dropped.
- **Tested against fakes, so check new layouts against the real API.** `test/cards.json` mirrors Scryfall's shapes per layout (top-level `colors` missing on transform, MDFC, and reversible cards; faces without `colors` on adventure and flip cards), and `test/fake-scryfall.js` answers like `/cards/collection`. When Scryfall adds a layout, check a real card of it before trusting the fixture.
- **Progress is staged, and only stage changes are announced.** `onProgress` reports read, lookup, retry passes, and sort, with cards found and an estimate from the measured time per request (never faster than the pace). The page puts the stage in a `role="status"` line and the counters in a plain line beside a `<progress>`, so screen readers hear "Looking up 7,500 cards" once, not every tick. A 429 shows a countdown. **Stop** aborts through an `AbortSignal` that reaches `fetch`, the pacing sleeps, and the bulk reader.
- **Bulk files are streamed, never held whole.** `readBulk` splits the array with `arraySplitter` (a brace- and string-aware scanner that carries a partial object across chunks, tested at every two-cut boundary) and keeps a ~300-byte slim copy of each card, indexed by the same keys as the API lookups. `resolve` checks it before the API, and `offline` skips the API. A 327 MB, 110,000-card file sorted a 9,000-row export in 3.8 s (~400 MB of memory) from the CLI and 4.2 s in Chromium, with no requests; a re-sort in the page reuses the parsed file. Reading from disk never waits on anything, so `readBulk` gives the event loop a turn every 50 ms, or the page wouldn't repaint or take Stop until the end. Default Cards lacks non-English printings' IDs; those rows find their English printing by set and collector number, which has the same colors.
